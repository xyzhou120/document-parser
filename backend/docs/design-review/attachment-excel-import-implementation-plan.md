# 附件 Excel 导入与解析结果版本：开发任务计划

状态：已获用户确认并完成首版代码与本地验证（2026-10-15）；真实来源接入和部署灰度待执行。本文保留实施顺序与验收要求，第 6 节记录实际实现和验证边界。设计基线见 [设计讨论稿](../attachment-excel-import-design-discussion-2026-10-15.md)，部署步骤见 [运行手册](../attachment-excel-import-operations.md)。

最新范围调整：Excel 仅为开发期快速进入解析流程的辅助入口；不做工作簿/链接加密、导入数据脱敏或密钥管理。字段契约与登记/解析服务共用，后续 MQ、HTTP 等只增加入口适配。来源策略默认无需配置，保留基本格式、大小和超时检查。

## 1. 首期范围

首期把 Excel 作为一种文件登记入口：读取模板、校验并预览、确认有效行、按 `attachment_id` 幂等登记、下载 PDF、复用或创建文件内容修订、启动当前可靠 PDF 解析流程、保存业务属性和结果版本。

Word、Excel、DWG 只登记业务属性和来源链接，不下载内部副本，不进入解析队列。MQ、定时拉取和手动拉取附件接入器不在本期实现，但登记服务要成为后续接入器的统一入口。

一个物理 `Document` 首期对应一个执行业务范围：一个来源附件、一个煤矿、一个上游清单和一个所属周期。暂不实现同一物理文档同时承载多个清单/周期的独立当前结果。

初提、补提、全量重提均创建新的结果版本。流程完整走完时自动冻结版本快照并切换当前版本；流程未完成、失败或被取消时，旧的有效版本继续作为当前版本。首期全量重提复用兼容的 PDF 内容处理结果，只重新执行字段提取；重新 OCR 或重新生成内容修订作为后续独立操作。

## 2. 依赖关系与实施顺序

```text
T0 领域契约与状态机
 ├─> T1 数据模型与迁移
 │    ├─> T2 Excel 预览/校验
 │    ├─> T3 来源附件幂等与导入观察
 │    └─> T4 下载任务与 PDF 文件修订
 │          └─> T5 可靠解析启动适配
 │                 └─> T6 结果版本/自动当前切换/历史快照
 │                        ├─> T7 文件列表与历史 UI
 │                        └─> T8 批次运营、重试与恢复
 └─> T9 权限、容量、安全和可观测性

T1/T2/T3/T4/T5/T6 完成后才能进行 T10 端到端验收与灰度。
T2、T3、T9 可在 T1 的领域字段确定后并行；T7 需要 T6 的读模型契约；T8 需要 T4/T5 的状态契约。
```

## 3. 任务分解

### T0：领域契约、状态机和兼容边界

目标：把设计讨论稿中的身份、生命周期和状态名称固定，避免后续接口各自解释。

主要工作：

- 固定导入字段契约：`mine_code`、`mine_name`、`report_time_raw`、`update_rate`、`cycle`、`file_name_id`、`file_name`、`attachment_id`、`attachment_name`、`attachment_link`。
- 固定周期规范化：保留原始值；`report_time` 中的 `00` 不转成日期 1 日；保存 `period_type`、`period_key`、规范化状态。`update_rate=0` 表示非更新型。
- 固定格式策略：PDF 可下载、留存和解析；Word/Excel/DWG 只登记和展示“暂不支持解析”。
- 固定导入状态、下载状态、解析状态、结果版本状态四个维度，避免把登记完成显示成解析完成。
- 固定操作意图：`INITIAL_EXTRACT`、`INCREMENTAL_EXTRACT`、`FULL_REEXTRACT`、`RETRY`。重试同一操作请求沿用原版本号；用户再次发起新的重新提取创建新版本。
- 固定“流程完整”的判定：遵循可靠执行器聚合契约，全部目标完成搜索/证据闭合；允许 `not_found`、`review_required`，不要求每个目标都有可用事实。`incomplete` 表示流程未闭合，不能定版为当前结果；即使执行状态为 `done` 也判失败。
- 固定当前结果选择：只读取自动完成的版本指针；运行中/失败/未完成版本只能作为最近任务显示。

交付物：状态枚举、状态转换表、API 错误码和幂等语义文档；领域服务接口草图。

验收：同一条附件从登记、下载、初提、补提、重提、失败、恢复到当前版本的状态序列唯一且可解释。

### T1：数据模型、唯一约束和增量迁移

目标：持久化上游业务属性、来源身份、导入观察、文件修订、结果版本及不可变快照。

主要工作：

- 增加来源附件身份表：来源系统、稳定唯一 `attachment_id`、当前 PDF 文件修订、登记状态和时间。数据库唯一约束以来源系统 + `attachment_id` 为准。
- 增加业务范围/附件登记表：煤矿、上游清单 ID/名称、所属周期原始值和规范值、与 `Document` 的一对一首期关联。
- 增加导入批次扩展：Excel 文件/模板版本、工作表、行号、原始行 JSON、导入观察、校验结果和操作者。现有 `BatchItem(batch_id, client_key)` 约束保留，增加跨批次来源身份关联。
- 增加原文件修订表：文件 SHA-256、大小、MIME/签名、对象存储键、来源链接摘要、获取时间、获取状态。上游正常替换产生新 `attachment_id`，同 ID 不同内容作为异常修订记录，不自动覆盖当前。
- 增加结果版本表：版本号、操作意图、父版本/父快照、绑定内容修订、规则/模型/策略快照 hash、流程状态、开始/结束时间、当前切换时间。
- 增加不可变结果快照和快照字段成员表：目标字段、字段修订、事实/证据引用、继承来源、统计快照、人工复核修订和失效水位。
- 增加当前版本指针和 CAS 版本号。明确它与 `DocumentProcessingHead.current_parse_run_id` 的职责，首期一个 Document 一个执行业务范围，不建立两个互相竞争的当前真相。
- 增加必要索引：来源附件唯一键、矿井、上游清单、周期类型/周期键、附件名称、格式、当前版本、最近任务状态、批次和创建时间。
- 编写 Alembic 迁移和 `init.sql`/部署初始化同步。旧 Document/ParseRun 只建立兼容关联；无法证明已完成或冻结配置的旧记录标为历史信息不完整，不按创建顺序虚构版本。

涉及文件：`backend/app/models/database.py`、`backend/app/models/batches.py`、新增领域模型文件、`backend/migrations/versions/`、`backend/migrations/init.sql`、`deploy/dependencies/postgres/init/001_schema.sql`。

验收：迁移可重复执行；唯一约束可阻止跨批次重复；快照表禁止更新/删除；旧数据查询不报错且不伪造当前版本。

### T2：Excel 预览、解析和确认接口

目标：支持上万行批次的流式/分块校验，预览不产生下载、对象或解析任务副作用。

主要工作：

- 新增 Excel 上传预览 API：识别表头、保留文本型 ID、校验必填列、格式、重复 `attachment_id`、周期编码和清单映射。
- 支持分块读取和后台校验任务，不把上万行全部放在浏览器内存；预览结果分页并返回汇总计数。
- 每行返回工作表/行号、可登记、待清单映射、暂不支持格式、重复、业务冲突、无效等明确原因。
- 新增确认 API：接受用户选择的有效行/清单分组，冻结模板/映射版本，写入导入批次和条目；有效行独立受理，单行错误不回滚整批。
- 增加行号与错误明细导出；导入业务字段和链接按原值保存、返回。
- 按 `file_name_id` 提供成组映射与启动入口，避免导入后逐条修复。

涉及文件：新增 `backend/app/api/imports.py`、`backend/app/services/excel_import_service.py`、`backend/app/schemas/imports.py`、前端导入服务和页面。

验收：预览前后数据库/对象存储/解析任务数不增加；100 行模板和模拟上万行均能分页预览；混合有效/无效批次只受理有效行；重复行可定位到 Excel 行号。

### T3：来源附件幂等与导入观察

目标：让重复 Excel、重复批次和并发确认只复用已有附件，不重复解析。

主要工作：

- 实现 `source_system + attachment_id` 的锁定查找和幂等登记。
- 同 ID 同内容：关联既有 Document/文件修订，已有兼容结果则不重新调用模型；写入本次导入观察。
- 文件名或链接变化：保存业务属性修订，不创建新附件。
- 不同 ID 相同指纹：允许共享内部对象/前处理缓存，但保留各自业务属性；字段事实只有在规则、内容、配置、业务范围和授权兼容时才复用。
- 同 ID 不同指纹：记录异常，不自动覆盖、切换或继承；进入人工处理状态。
- 显式重新提取必须有独立操作请求 ID，不能被文件指纹去重逻辑吞掉。

涉及文件：来源附件服务、`backend/app/services/batch_service.py`、`backend/app/api/batches.py`、数据库唯一约束和并发测试。

验收：同批/跨批重复、并发确认、不同 ID 同内容、同 ID 内容异常四组场景下，附件、文件修订、解析任务和导入观察数量符合预期。

### T4：下载任务、PDF 检测与文件修订

目标：受控获取 PDF，并保证重试/取消/恢复不会由旧 worker 覆盖新状态。

主要工作：

- 增加 PDF 下载任务状态：`QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED_RETRYABLE`、`FAILED_TERMINAL`、`CANCELLED`、`TYPE_UNSUPPORTED`。
- 按模板 HTTP(S) 链接下载，来源白名单为可选策略；保留大小、超时、并发和 PDF 类型检查。
- 下载后校验文件签名、MIME、扩展名和大小，计算 SHA-256，写入隔离暂存对象，再事务性登记正式文件修订。
- 为下载领取实现租约、心跳、到期回收和 fence/代次校验；旧 worker 只能写审计或待清理对象。
- 下载以数据库持久化状态作为任务账本，Celery 消息只负责唤醒，Beat 有界扫描补发；解析继续使用既有 durable outbox。对象写入成功但数据库失败、数据库成功但派发失败均可恢复。
- 非 PDF 行不创建下载任务，显示“暂不支持解析”。

涉及文件：新增下载服务/任务、`backend/app/storage.py`、`backend/app/tasks.py`、配置和安全策略。

验收：取消后旧任务晚完成不能改变当前文件；租约过期可接管；重复派发不会重复创建正式修订或解析任务；PDF 类型不符能终止并给出行级原因。

### T5：可靠解析启动适配

目标：Excel 登记和人工入口都通过同一个可靠解析启动服务，不再直接复制 legacy Celery 创建逻辑。

主要工作：

- 将登记条目映射到 `Document`、业务范围、PDF 文件修订和 active `ContentRevision`。
- 为每次初提/补提/全量重提生成独立版本号、操作请求 ID、父版本/父快照和规则/模型/策略快照。
- 复用已有 `reliable_extraction_service.start`、内容准备、field jobs、outbox、lease/fence；补齐版本元数据和 operation_kind。
- 首期全量重提复用兼容内容修订；提供明确的“内容修订不兼容”错误，为后续重新 OCR 入口留扩展点。
- 让旧增量、批次 retry、人工重新提取入口统一调用领域服务，禁止绕过活动任务互斥和父快照校验。

涉及文件：`backend/app/api/parse.py`、`backend/app/api/batches.py`、`backend/app/services/reliable_extraction_service.py`、`backend/app/services/content_preparation_service.py`、`backend/app/tasks.py`。

验收：同一业务范围同时发起补提和全量重提时，只有符合父快照 CAS 的版本可自动切换；旧版本和失败版本不被覆盖；启动请求重复提交不新增运行。

### T6：自动版本定版、快照和历史读取

目标：流程完成自动形成当前版本，历史结果可重现。

主要工作：

- 根据可靠执行器聚合状态：`COMPLETED` 或 `COMPLETED_WITH_REVIEW` 才可冻结附件 `COMPLETED` 版本；其他状态保留旧当前结果，区分 `RUNNING`、`INCOMPLETE`、`FAILED`、`CANCELLED`。
- 完整流程完成时，在同一事务内冻结快照字段成员、继承来源、证据、统计、规则/模型/内容配置和人工复核水位。
- 以创建时父版本/父快照 CAS 原子更新当前版本指针；V2 未完成/失败时继续保留 V1 当前。
- 改造 facts 读取，历史按快照读取，当前附加撤回/失效状态并列展示，不动态重算旧快照。
- 改造 `/parse/results`：一行一个业务范围，读取当前完成版本；同时返回最近任务状态、最近任务耗时和失败原因。
- 扩展运行详情：当前版本、版本状态、操作类型、父版本、字段统计、流程阶段和历史版本。

涉及文件：`backend/app/services/content_publish_service.py`、`backend/app/services/fact_service.py`、`backend/app/api/parse.py`、`backend/app/api/documents.py`、相关 schemas。

验收：V1 完成→V2 运行中/失败→V2 完成的序列中，列表始终显示正确当前版本；5+3 补提成为新版本并显示 8 个目标；旧版本证据和统计可重现。

### T7：文件列表、历史版本和导入前端

目标：让用户按业务维度查询附件，区分当前结果和最近任务，并查看历史版本。

主要工作：

- 新增 Excel 导入页：上传、预览、分组映射、筛选确认、进度和错误导出。
- 扩展 `DocumentList`：煤矿、清单、周期、附件名、格式、导入批次、当前结果状态、最近任务状态筛选；支持分页、空结果和大批次。
- 默认列显示附件属性、当前版本、字段统计、匹配分、耗时、首次登记时间、最近结果更新时间。
- 操作区提供查看当前结果、历史版本、执行记录、补提、全量重提、失败重试；按钮状态来自真实状态机。
- 历史页按 V1/V2/V3 展开，展示本轮规则/模型/内容、字段来源、证据、继承关系和统计。
- Word/Excel/DWG 行显示登记成功但暂不支持解析，不显示虚假的解析完成状态。

涉及文件：`frontend/src/pages/DocumentList.tsx`、新增导入/历史页面、`frontend/src/services/batches.ts`、新增 import/version service、`frontend/src/types/api.ts`、路由和样式。

验收：按煤矿/清单/周期组合筛选、分页和空结果正确；当前结果与最近任务不混列；查看和导出默认绑定当前完成版本；历史页面不因当前撤回或新任务而改变旧快照。

### T8：批次运营、恢复和容量控制

目标：支持上万行批次稳定运行，并可按行恢复。

主要工作：

- 将批次汇总拆为登记、下载、解析、当前版本四类统计；未知、待映射、暂不支持、失败不误算完成。
- 增加按批次/清单分组暂停、继续、仅重试失败项和失败导出。
- 下载全局并发、批量自动初提并发和既有模型调用配额分层限制；恢复扫描有界。容量与人工单文件竞争仍需部署灰度实测，不把配置并发数当吞吐保证。
- 增加 Beat/定时恢复：失租下载、未派发 outbox、过期暂存对象、失败重试和孤立条目。
- 增加运营指标：各阶段积压、最老等待时间、重试耗尽、租约失效、版本自动切换失败和孤立对象。

涉及文件：`backend/app/services/batch_service.py`、`backend/app/tasks.py`、Celery Beat 配置、运维脚本和观测接口。

验收：服务重启后批次可继续；单行失败不影响其他行；状态汇总准确；限流和恢复行为可观测且有审计记录。

### T9：权限、安全和数据保护

目标：在附件来源、内网下载和历史结果场景中保持访问边界。

主要工作：

- 明确首期共享工作区或煤矿范围授权；如需要煤矿隔离，以业务范围为授权入口覆盖导入、列表、历史、原文件、证据、导出和重提。
- 开发期工作簿、业务字段和附件链接直接保存，不增加加密、脱敏和密钥配置。版本业务属性快照保留来源链接；模型运行配置仍沿用已有凭据排除逻辑。
- Excel 内容只作为业务数据，不执行公式或其他指令；附件链接检查为有效 HTTP(S)，默认不要求配置来源白名单。
- 限制上传大小、Excel 行数/列数、单批次任务数、下载大小、模型预算和重试次数。
- 记录操作者、原因、来源批次、请求 ID、版本切换和异常处置审计。

验收：首期按可信共享开发工作区复用现有 `read`/`parse` scope；不配置导入密钥即可上传、预览、登记和下载；原始业务属性与链接可查询，格式/大小限制有效。正式来源权限和鉴权方式以后再按真实流程适配。

### T10：测试、迁移演练和灰度

目标：在不破坏现有上传/解析路径的情况下逐步上线。

自动化测试：

- 领域状态转换、周期规范化、`attachment_id` 唯一和重复导入幂等。
- Excel 预览无副作用、分块校验、混合有效/无效行、错误导出。
- 下载 URL/类型/哈希、租约到期接管、旧 worker fence、outbox 恢复。
- 版本 CAS、自动定版、V1/V2 当前指针、5+3 补提、字段继承阻断、历史快照不可变。
- API：导入预览/确认、批次详情、列表筛选、当前结果、历史版本、重提和失败重试。
- 前端类型检查、构建和关键页面交互测试。

迁移演练：

## 4. 计划完成标准

- Excel 导入产生可追踪批次、行状态和错误原因，重复 `attachment_id` 不重复解析。
- PDF 文件可以安全下载、留存、校验并进入可靠解析；非 PDF 只登记。
- 每轮初提、补提、全量重提都有独立结果版本；流程完整自动切换，失败/未完成不覆盖当前有效版本。
- 列表、详情、导出和历史读取同一个当前版本契约，历史快照可重现。
- 上万行批次可恢复、可限流、可观测，旧入口不会绕过新门禁。
- 相关后端测试、前端构建、迁移检查和灰度验收全部通过；未验证的外部内网附件连接单独标记，不冒充生产验收。

## 5. 已确认的实现假设

本版按“全量重提复用兼容的 PDF 内容处理结果，只重新执行字段提取”实现；重新 OCR/重新生成内容修订保留为后续独立操作。身份、格式、自动定版、失败保留旧版本和导入复用规则均已确认并落地。

### 实际实现与原任务草案的对应关系

- 物理模型为 6 张表：`attachments`、`attachment_file_revisions`、`attachment_versions`、`attachment_imports`、`attachment_import_rows`、`attachment_checklist_mappings`。业务范围与来源身份合并在附件表，字段成员/事实/证据/配置存入版本 JSON 快照，以数据库触发器禁止定版后变更；没有再建独立成员表。
- 原文件相同可共享对象；同来源 ID 重复导入复用附件且保留导入观察。同附件全量重提复用兼容前处理；跨 ID 字段事实复用首期保守关闭，不能把共享文件解释为共享业务结果。
- 新实现入口为 `api/attachment_imports.py`、`api/attachments.py` 与 `services/attachment_*`；前端为 `ExcelImport`、`AttachmentList`、`AttachmentDetail`。原任务中示例文件名不是最终新增文件名。
- 统一字段校验和周期规范化在 `services/attachment_input.py`，不依赖工作簿；Excel 适配器和附件登记服务共用。未来 MQ/HTTP 适配器只需转换模板所表达的 10 个业务属性，再调用登记服务。
- 下载采用持久化状态账本 + Beat 恢复；解析继续复用 outbox/lease/fence。批次控制只作用于本批新登记附件（`REGISTERED`），重复关联（`REUSED`）仍可查看但不会由后来的批次暂停/取消原任务。
- 旧文档继续使用旧列表/旧链接读取，未按运行时间伪造 V1/V2；新受管附件通过当前快照读取，补提继承字段保留原始运行 ID 以支持复核与证据查看。
- T10 的本地自动化、迁移演练、页面检查已完成；真实来源 TLS/鉴权、OCR/模型、容量压测及业务库灰度为部署验收事项，尚未完成。
